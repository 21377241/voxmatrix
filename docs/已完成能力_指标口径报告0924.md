  - AISHELL-4 / AliMeeting：远场原始录音**连续裁剪**。
  - AMI：用 SDM 逐句片段按时间戳**叠加还原**（adapted）。
  - CHiME-6：窗内多数句所属的参考阵列（ref array）**4 通道取均值**。
- **Full Index**：构建产物在 `/mnt/afs/eval_data/windowed_ondevice/`（`scripts/build_windowed_ondevice_indexes.py`，坏样本 0）；同步到仓库 `mesh_eval/data/full/{long_form_asr,diarization,speaker_attribution}/`（`scripts/build_full_windowed_indexes.py`，2026-09-30），文件名与 Native 相同，保留全部可用行（含缺档组），Native 80 条与 Full 对应行逐字一致。旧 30–60s 索引移到 `mesh_eval/data/full/long_form_asr/legacy_30_60/`。

### Reference 口径

- 窗内全部 segment 按开始时间排序后拼接，**包含重叠插话**。边界对齐保证不存在被截断的半句。
- 构建时剥离金标中的尖括号标记（`<sil>`、`<%>` 等）。

### 指标

| Benchmark 语言 | 主指标 | 聚合 | Agg |
|---|---|---|---|
| 中文（AISHELL-4、AliMeeting） | CER | corpus-level | `wer-zh-windowed` |
| 英文（AMI、CHiME-6） | WER | corpus-level | `wer-windowed` |

- 与句级 ASR 口径一致：总编辑距离 / 总参考字（词）数。分档只是在同一口径下多报 `window_bucket/<档>/wer(%)` 和 `window_bucket/<档>/sample_count`，不另设权重。
- **已知偏差**：中文 TextNorm 会把 hyp 中的阿拉伯数字归一，但金标有时写成汉字读法（如「零零六」），这类不一致会抬高 CER。与其他中文 ASR 槽保持同一口径，不做特判，只在此注明。

## 3. Audio Caption

### 任务与数据

- 任务：音频生成英文自然语言描述。
- AudioCaps：1 音频对应 1 条 reference，Full Index 4,411 条。
- Clotho：1 音频对应 5 条 reference，Full Index 1,045 条；模型每个音频只推理一次。

### 指标

| 指标 | 用途 | 聚合 |
|---|---|---|
| CIDEr | TF-IDF 加权 caption 相似度 | COCO corpus-level |
| SPICE | 对象、属性、关系语义 | COCO corpus-level |
| SPIDEr | CIDEr 与 SPICE 组合 | COCO corpus-level |
| BLEU / METEOR / ROUGE-L | 词面、语言和句序匹配 | COCO corpus-level |
| FENSE | Sentence-BERT 语义相似度 + 流畅性惩罚 | sentence-level 后取平均 |

### FENSE 口径

- 使用 `paraphrase-TinyBERT-L6-v2` 和 `echecker_clotho_audiocaps_base`。
- FENSE v0.1 当前实现对多 reference 的语义相似度取平均。
- fluency error probability > 0.9 时，分数乘以 0.1。
- FENSE 是补充语义/流畅性指标，不直接判断 audio grounding。
- 20 条历史 prediction 后处理：AudioCaps FENSE 0.5500，Clotho FENSE 0.4060。

### 指令 / pred / ref 形态

```text
指令: [audio enroll] [audio test]
      Determine whether both recordings contain the same speaker.
      Return JSON only as {"same_speaker": true, "score": 0.0},
      where score is confidence from 0 to 1 that they are the same speaker.
pred: {"same_speaker": true/false, "score": 0.0–1.0}
      （可带 ```json 围栏；有 score 时后续判定以 score 为准）
ref:  label / text ∈ {0,1}；same_speaker bool；reference_obj 含二者
→ 样本级抽出 verification_score / verification_label
→ MeshAgg：overall/eer、overall/auc；acc@0.5 仅诊断
```

### 指标

| 指标 | 角色 | 含义 | 好坏 |
|---|---|---|---|
| **EER** | **主指标** | 扫描阈值使 FAR≈FRR，取平均错误率 | **越小越好**（0 完美） |
| **AUC** | 辅主指标 | 随机一对（同人分、异人分）中同人分更高的概率 | **越大越好**（1 完美，0.5 随机） |
| `speaker_verification_acc` | 诊断 | 固定阈值 0.5：`score≥0.5` 判同人后与金标比对 | 仅对照，不当主分 |

算分要点（`SpeakerVerificationEvaluator` + MeshAgg）：

1. 解析 JSON，取值优先级：`score` → `similarity` → `same_speaker` → 原文。
2. 得到 `verification_score`（浮点）与 `verification_label`（1=同人，0=异人）。
3. **acc@0.5**：`predicted = (score ≥ 0.5)`，样本级 0/1 再平均。
4. **EER**：按金标拆成同人/异人两组 score；对候选阈值 \(t\) 算  
   \(\mathrm{FAR}(t)=\#\{\text{异人且 }score\ge t\}/\#\text{异人}\)，  
   \(\mathrm{FRR}(t)=\#\{\text{同人且 }score< t\}/\#\text{同人}\)；  
   取 \(|\mathrm{FAR}-\mathrm{FRR}|\) 最小处的 \((\mathrm{FAR}+\mathrm{FRR})/2\)。
5. **AUC**：Mann–Whitney 式，对每个同人分 \(p\)、异人分 \(n\)：\(p>n\to1\)，\(p=n\to0.5\)，\(p<n\to0\)，再除以对数。

`min_dcf` 未实现，本能力不评。

### 为什么主分不用 acc@0.5

- **阈值任意**：同一套分数排序，换门槛（0.5 / 0.3 / 0.7）acc 会变；Omni 分数常两极（0.95 / 0.1），固定 0.5 不能代表「分得开」。
- **官方 verification 协议报 EER/AUC**，不是固定阈值 accuracy。
- **acc 丢校准信息**：`score=0.51` 与 `0.99` 在 acc 里同为对；EER/AUC 看相对排序与最优门槛错误率。
- 小样本上 acc 噪声大；EER/AUC 更贴近「同人分是否整体高于异人分」。

因此：**EER 为主、AUC 为辅、acc@0.5 仅 diagnostic**。

```text

      matches enrollment, or {"should_execute": false} otherwise.
pred: {"should_execute": true|false}（可带 ```json 围栏）

### 指标

| 指标 | 角色 | 含义 | 好坏 |
|---|---|---|---|
| **target_speaker_acc** | **主指标** | pred `should_execute` 与 ref 是否一致（样本级 0/1 平均） | 越大越好 |

- 门控任务需要同时看 **不安全误开** 与 **该开却拒**；二者之和 ≈ 1−acc（在全部可解析时），但分开报才能判断偏置方向。

```text

      {{text}}
pred: 生成 wav 路径（Omni 常先出 {"text":"...","audio":"/...wav"}，经 extract_audio 抽出）
ref:  text（待读原文）
→ Whisper ASR(hyp) vs 原文 → wer%；content_acc = max(0, 1 − WER)
```

### 指标

| 指标 | 角色 | 含义 | 好坏 |
|---|---|---|---|
| **content_acc** | **主指标** | `max(0, 1 − WER)`；语料级由 corpus `wer%` 反推 | **越大越好** |
| intelligibility | 别名 | 与 content_acc 同值 | 越大越好 |
| **wer%** | 辅 | Whisper(hyp) vs 原文的词错误率 ×100 | **越小越好** |

算分要点（`SeedTTSEvalASRWER` + MeshAgg）：

1. pred 经 `ExtractOmniAudioPath` 得到存在的 wav 路径。
2. 用 Whisper（`seed-tts-whisper` + `whisper-asr-en`）转写生成音 → `transcription`。
3. 去标点后英文小写，`jiwer` 算 WER；样本级 `content_acc = max(0, 1 − WER)`（WER 可 >1，acc 截到 0）。
4. **语料聚合**：MeshAgg 对全部 `transcription`/`label_text` 再算 **corpus wer%**，再令  
   `overall/content_acc = max(0, 1 − corpus_wer%/100)`（`aggregation=corpus_error_rate`）。
5. 因此 **overall content_acc ≠ 样本 content_acc 均值**；长句权重大，短句高 WER 会被稀释。

#### 为何主分用 content_acc（corpus）而不是样本均值

- 与英文 ASR 主榜的 corpus WER 一致：总编辑代价 / 总参考词数。
- 样本均值对极短句敏感（2–4 词一条错一词即 25–50%），不适合单独作正式主分。
- 报告时可并列样本均值作诊断，但 **overall 以 corpus content_acc / wer% 为准**。

## 19. Instruction Following

### 任务与分轨原则

- 任务：听语音指令 → 按约束产出结果。
- **两套分、不合并**（见 [`待讨论问题.md`](待讨论问题.md) §7）：
  - **VoiceBench**：文本约束遵循（IFEval）
  - **VocalBench / zh**：全量**语音输出** + 听评 rubric
- FSC / SLURP 的 **Spoken SLU**（intent+slots）已独立为 Catalog 能力 **`spoken_slu`**，不在 IF 主路径；MASSIVE 不用（官方纯文本、无语音）。
- 禁止把 VoiceBench 与 VocalBench 平均成「一个 IF 总分」；也禁止与 LibriTTS `content_acc` 或 `spoken_slu` intent_acc 混榜。

| | VoiceBench | VocalBench / zh |
|---|---|---|
| Catalog | `instruction_following__voicebench`（ok） | `instruction_following__vocalbench` / `__vocalbench_zh`（diagnostic） |
| suite / 模型 | `main` / `qwen3-omni-local`（文本） | `tts` / `qwen3-omni-speech-local` + `extract_audio` + `two_phase` |
| 输出 | 自然语言**文本** | **生成 wav**（全量 `requires_audio_output=True`） |
| 评什么 | 格式/长度/关键词等文本约束是否满足 | 内容 + 交付约束（含情绪/语速等）；听生成音打分 |
| Evaluator | `mesh-ifeval`（官方 IFEval **规则 checker**，非 LLM） | `mesh-agent-rubric-audio`（**Thinking** Omni 听评；被测为 Instruct speech） |
| 主指标 | `constraint_satisfaction`（= `strict_prompt`） | `constraint_satisfaction`（rubric score ∈ [0,1]） |
| 区别一句话 | 「写对没有」 | 「说对没有（含怎么说）」 |

**判分来源说明**

- **VoiceBench**：Google IFEval 风格——每条题带 `instruction_id_list` + `kwargs`，对应本地 `instructions_registry` 里的**确定性检查函数**（如禁止逗号、词数、关键词出现次数等）。`strict` / `loose` 两档；主分取 `strict_prompt`（整题全部指令都过才算过）。**没有 LLM 参与打分**。
- **VocalBench（对齐官方 Following Rate）**：
  1. **语义级**（`instruction_semantic.py`）：按 Sub-category/Category 选用官方 **16 条 Judgment Criteria**，LLM 只输出 **Correct/Incorrect**（中文：**正确/错误**）；官方用 Qwen-Max，我们用 **Thinking** Omni 代判（被测仍为 Instruct speech）。
  2. **声学级**（`instruction_full.py`，主要针对前 200 / Paralinguistic）：语义 Correct 之后，再过 ASR–文本 WER&lt;0.2、emotion2vec 情绪概率&gt;0.5、语速时长窗等门控；后 700 条 Success≈语义 Correct。
  3. 主指标官方名 **Following Rate (FR)**；我们字段仍写 `constraint_satisfaction`（0/1），语义对齐 FR 的 Correct 位。
  4. **缺口**：声学门控（emotion2vec / 时长 / ASR WER）尚未接入 Native smoke；当前先落地官方语义 criteria + Correct/Incorrect，FR 完整复现待补声学级（见待讨论 §7）。

### 与官方的差异（需注明）

- **Judge 模型**：官方用闭源 API judge（VocalBench：`qwen-max-2025-01-25`；MT-Bench：GPT-4；AAB：`claude-opus-4-5`；MTalk：`gpt-4o-audio-preview` / `gemini-2.5-pro`），本仓统一本地 Thinking judge，绝对分与官方榜不可直接对比；为防 Thinking 耗尽 token，在官方 prompt 末尾追加一句输出格式约束，正文不改。
- **AAB**：只评 dialogue 视图（不含 tool/clarification 轮，这两类能力挂起）；离线无工具运行时，`Actual Functions` 恒为 none；历史用 golden（官方 rehydrated 模式同此），不是模型自己的上一轮回复。
- **MTalk**：只做 rubric；arena / ELO 需要两个模型成对比较，单模型不计算。细则保持官方原文，不额外补"对话中没有机会体现时算几分"的规则：ambient 类每条对话都设计了对应的背景事件或多人发言，按设计不存在"没有机会"。MTalk 评委的末尾约束换成单轮评委同款硬规则（`strict_output_rules`），并开启强制收尾（`force_close_thinking_tokens: 512`）：思考写满 2048 token 仍未结束时，补上结束标记再续写 512 token 输出 JSON；被强制收尾的判断记 `judge_forced_close_general/specific=1`。两项都只约束输出格式，不改评分逻辑。
- **长度**：AAB conversation-bench 后段 SUT 输入约 22k token、judge 约 28k token，均在 32k 内；回复超过 6000 字符时截断后送 judge。

### 分组

新增维度 `dialogue_category`（VocalBench Category、MT-Bench category、AAB 首个 category、MTalk type），MeshAgg 默认按 `[task, capability, benchmark_id, dialogue_category]` 出分组分。
